# The dashboard front-end

Extracted verbatim from CLAUDE.md, which now points here.

The dashboard's ONLY source is `internal/api/web/src/*.ts`; `npm run build` (tsc) compiles it to `internal/api/web/assets/*.js`, which is a **gitignored build output that is never committed**, embedded via `//go:embed`. Work only in the `.ts` — the `.js` is disposable, regenerated on demand, never hand-edited and never added to git. The embed names each `.js` file, so a missing one is a Go COMPILE error: `npm run build` must run before any Go build or test (CI's `build` job runs `npm ci && npm run build` ahead of `go-toolchain` for exactly this reason). CI's `web-check` job is the type-check gate (`npm ci` + `npm run build` on the locked toolchain, tsc exits non-zero on any error) and it FAILS if any generated `.js` is tracked (`git ls-files internal/api/web/assets/*.js` must come back empty) — so a second, staleable copy of the front-end can never re-enter the tree. Hand-written `assets/style.css` stays tracked. `assets/demo-data.js` is preview-only (NOT embedded); the CI `preview` job injects it to deploy a backend-free styling preview to buildhost per branch. Each `src/*.ts` emits its own standalone ES module loaded by its own `<script type="module">` tag in `index.html` — `rate-meter.ts` self-registers the `<rate-meter>` web component; `timeline.ts` self-registers `<gsm-timeline>` (types for its buildhost-URL component import live in the interim ambient shim `src/js-snippets-timeline.d.ts` — types only, keep it minimal). Adding an asset file means wiring it in **three** places: the `//go:embed` + hashed-URL machinery in `internal/api/dashboard.go`, the `index.html` script tag, and the `preview` job's copied-assets list in `ci.yml`. The node TEST HARNESS (`internal/api/testdata/browsercheck.ts` — the real-browser end-to-end frame check) is TypeScript too, type-checked against `src/` by `npm run check:harness` (`tsconfig.harness.json`, noEmit — node runs the `.ts` directly, so there is no build step and nothing lands in `assets/`); CI's `web-check` runs it, so a changed export signature fails the build instead of surfacing mid-measurement at runtime. `testdata/dashboardcheck.test.ts` is the second browser harness (`npm run test:dashboard`): it serves the built dashboard the way the preview job does and asserts from COMPUTED STYLE that chrome the code hides with `el.hidden` is really off screen — an author `display` outranks the UA's `[hidden]` rule, which is why `style.css` carries `[hidden] { display: none !important }` and why nothing off-browser can see the difference. Playwright (both harnesses) is deliberately NOT a devDependency — `testdata/playwright.d.ts` is a minimal types-only shim so `npm ci` stays light; `npm i -D playwright` to actually run it.
