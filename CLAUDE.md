# GitHub State Mirror

## Project Overview

A Go service that mirrors GitHub state into SQLite, providing a fast local API surface. This is a **cache** — the SQLite DB is disposable and gets nuked+recreated on schema version changes.

## Architecture

- `internal/actor/` — Context-based principal-key propagation + display shortening + verified display-name propagation (`WithName`/`NameFromContext`, set only from GitHub-verified answers: a user's login, an app's slug, an installation's account login) (stdlib-only, safe to import from anywhere). A "principal" identifies WHO is asking (`user:<id>`, `app:<id>`, `app-installation:<id>`, or a token fingerprint) — it gates what the cache REVEALS, never what it STORES; the name is display-only and never a key.
- `internal/freshness/` — Generic cache freshness framework (zero GitHub knowledge); `Manager.Drain` waits out in-flight detached fetches at shutdown
- `internal/database/` — SQLite schema + sqlc-generated queries (`dbgen/` is codegen, do not edit)
- `internal/ghdata/` — Domain store wrapping sqlc with transaction logic: global truth writes (`SyncOrgTruth`, `UpsertPRWithChecks`, ...), the reveal layer's `access_grants`/`deny_cache`, and the dashboard reads. The grant-writing paths (`SyncOrgTruth`, `RecordGrant`) opportunistically sweep expired grants/denials after committing (`maybePruneAccessControl`: best-effort, log-on-error, throttled to once per ~10 min via an atomic last-run stamp); reads (`HasGrant`, `GrantsByPrincipal`, `CountLiveGrants`, `ListGrantPrincipals`) all filter on expiry regardless
- `internal/ghclient/` — GitHub REST + GraphQL API client (includes the in-memory token→identity cache behind `ResolveTokenIdentity` and `AppAuthenticator` for GitHub App JWT / installation-token minting; `Installations` paginates past 100). `doJSON` — the shared HTTP exchange behind the REST/GraphQL helpers (`GetOrgData`, `GetOwnerData(WithProgress)`, `OwnerRepoVisibilities`, `Installations`, `InstallationToken`, `GetRateLimit`) — **retries transient failures**: 502/503/504/429 and network errors, 3 attempts total with a short backoff (500ms/2s, a parseable `Retry-After` raises the floor but is capped at 10s so a huge value can't wedge a deadline-bounded fetch; bodies are buffered once so retries resend them). Deliberately NOT retried: authoritative 4xx answers (the reveal layer and deny-cache semantics depend on them), the caller's own context cancellation/deadline, and GraphQL-level `errors[]` bodies (HTTP 200 semantic answers, checked by the callers). The passthrough proxy does not go through `doJSON` and is untouched. Two GraphQL fetch families: the identity-locked `GetOrgData` (`organization(login:)`, the lazy /graphql route's byte-frozen contract) and the sync/checker-private `GetOwnerData` + `OwnerRepoVisibilities` (`repositoryOwner(login:)` — resolves Users AND Organizations; selects extras the locked query must never grow: `isArchived`, `labels(first: 100)`, `autoMergeRequest`, the `visibility` enum — the DATA query now carries per-repo `visibility` too (lowercased in `convertRepo`), so a fleet-refresher/consistency-apply `SyncOrgTruth` STAMPS visibility into truth, while `UpsertRepo`'s non-empty guard means the visibility-less locked org query can never blank a stamped value; before this, refresher-synced rows sat at `''` = fail-closed unknown — the 2026-07-20 report's 203 `visibility_unknown` entries covering essentially every PazerOP/read-only-reference repo). Both owner queries pin **`ownerAffiliations: OWNER`** — the connection's default `[OWNER, COLLABORATOR]` made a User's listing include repos the login merely *collaborates* on, under their real owners, which `convertRepo`/`convertPR` then keyed by the QUERY login (the collaborator-repo bleed: junk `<user>/<name>` truth rows with foreign `name_with_owner`/`url`, double-counted PRs). Belt-and-braces, every repo-conversion loop (org and owner alike, plus the visibility loop) also **DROPS any node whose real owner** (`nameWithOwner` prefix, else `owner.login`) **differs case-insensitively from the queried login**, logging each drop (`dropForeignRepoNode` in `queries.go`) — drop, never re-key, so one owner's sync can never absorb truth rows or mint grants across owners; this also covers the identity-locked org query with zero query-text change (`TestOrgQueryUntouched` still passes) and kills the visibility map's bare-name collision hazard (a same-named foreign node clobbering an owned repo's visibility entry). SchemaVersion 14's deploy-time nuke cleaned up the junk rows a corrected re-run could never delete (sync never deletes repo rows; the PR reconcile only visits fetched repos). `SetRateObserver` installs the passive rate-limit hook: every response the client sees is reported to `internal/ratemeter`, labeled by the ctx principal when set, else by the credential's shape (`app-jwt` for a JWT, a short `token:<fp12>` fingerprint otherwise — never the raw token). `SetExchangeObserver` wraps the client's transport so EVERY call it makes — through any helper, present or future, one event per real attempt — is timed onto the dashboard's Timeline chart with the same identity labeling (a gap on that chart is a bug)
- `internal/reqtimeline/` — In-memory ring of TIMED traffic events behind the dashboard's "Timeline" chart. **Everything the mirror exchanges is on the chart; a gap is a bug** (operator ruling 2026-07-15 — the first cut scoped out ghclient's background traffic as "deliberately not recorded" and was REVERTED for it; never reintroduce an observability exclusion). Recorded, each with its REAL measured duration (never faked to an instant, never inflated): every incoming webhook delivery attempt WHATEVER its outcome (verified receipt→dispatch-complete; rejected/unverified/unparseable deliveries record on the fixed "⇐ (unverified)"/"⇐ (unknown)" lanes — attacker-controlled headers never mint lanes, claimed metadata rides only as clamped tooltip detail); every inbound data-API request the mirror serves — hits, misses, passthroughs, writes, errors — timed end-to-end via `requestLog.observe*` off the router's `stampRequestStart` receipt stamp; the mirror→GitHub leg of every cached-route miss (`fetchUpstream`, disposition `upstream`); every reveal probe (`probe`); every call the mirror's own ghclient makes — identity resolution, app verification, token mints, fleet-refresh/consistency GraphQL, rate-limit polls — via the transport-level `SetExchangeObserver`, one event per real attempt (disposition `internal`); the github.com login relays (`relay`); and every outbound subscriber-notification attempt on the "⇒ notify" lane (per-attempt, with status/attempt/final). The one uncharted surface is stated openly: the dashboard's own UI endpoints (`/api/*`, login, assets) — the chart polling itself would recursively fill the chart with the act of viewing it; if the operator wants those too, add them, don't argue. Read by the admin-only `GET /api/timeline?since=<id>` cursor endpoint. Bounded by 24h retention (lazy eviction on write AND read; no background timers) plus a 100k count cap; nil-receiver-safe; in-memory on the requestLog/ratemeter stance (live view, not an audit log; resets on restart). Lanes stay bounded by construction: "⇐ <event type>" for webhooks, `normalizeRoute`'s route shapes for requests/exchanges, "⇒ notify" — never per-URL, never from untrusted input.
- `internal/ratemeter/` — Passive rate-limit observation: a thread-safe, IN-MEMORY store of the latest `X-RateLimit-*` reading per (identity, resource), fed by every upstream path (passthrough proxy, cached-route miss fetches, reveal probes, ghclient calls) and read by the dashboard's "Rate limit" tab. Each observation also carries the identity's verified display `Name` when the caller supplied one (display-only, never part of the key; a nameless re-observation keeps the last known name). Deliberately in-memory (the `requestLog` stance: live view, not an audit log — and a DB table would force a cache-nuking SchemaVersion bump for sub-hour-ephemeral data); bounded at 512 entries (oldest-ObservedAt evicted); **dead observations age out lazily** — an entry whose reset moment has passed is pruned (an active identity is re-observed with a fresh future reset on every request, so a past reset means the identity stopped calling), and a zero/garbage-reset entry is pruned once its ObservedAt is >1h old (GitHub's longest standard window) — swept on Observe AND Snapshot, NO background goroutine/timer (the kv lazy-expiry stance; the 512 cap stays as the size backstop); the dashboard's `<rate-meter>` renders any still-visible past reset honestly as "reset …h ago · stale", never "resets now"; methods are nil-receiver-safe; resets on restart
- `internal/auth/` — GitHub OAuth login + signed-cookie sessions for the dashboard (stdlib-only, no DB knowledge)
- `internal/sync/` — Bridge layer: the org list-sync fetcher, periodic refresh, webhook dispatch (always-apply), the global consistency checker
- `internal/webhook/` — Webhook HTTP handler + event parsing (dispatch is **synchronous**; the handler returns a per-delivery disposition in the response so GitHub's delivery record reflects whether the cache was updated). After each dispatch the handler hands the outcome to any `IngestNotifier` (variadic, optional, nil-safe — `internal/notify` implements it); the notifier call is non-blocking by contract, so the response to GitHub never waits on subscribers. An optional `DeliveryRecorder` (nil keeps it inert; `internal/api` adapts it onto `reqtimeline`) additionally observes EVERY delivery attempt with its real measured duration for the dashboard's Timeline chart: verified deliveries after dispatch, and rejected ones at the moment of refusal under the recorder-only dispositions `unverified` (bad/missing signature, unset secret), `unparseable` (verified, no event type), and `rejected` (wrong method, unreadable body) — the recorder must treat rejection metadata as untrusted (fixed lane, clamped detail), and GitHub-facing responses are unchanged.
- `internal/notify/` — Subscriber notifications ("mirror-ingest webhooks"): authenticated API clients register their own webhook endpoints (`/_mirror/subscriptions` CRUD, principal-scoped via requireAuth), and AFTER the dispatcher applies a delivery to global truth the mirror POSTs a compact, HMAC-signed JSON notification (`X-Hub-Signature-256`, GitHub's exact scheme) to every matching, authorized subscription — so consumers stop racing the mirror's ingestion with their own GitHub webhooks. Subscriptions persist in a SEPARATE SQLite config DB (`SUBSCRIPTIONS_DB_PATH`); delivery is detached, bounded, retried, auto-disabling, and reveal-gated fail-closed (see the doctrine bullet under Key Constraints). In-memory activity ring + counters back the admin-only `GET /api/notifications` JSON view (no dashboard tab).
- `internal/api/` — chi router, REST handlers, GraphQL cache assembler, the **reveal layer** (`reveal.go`), the GitHub passthrough proxy (`proxy.go`), the in-memory request-disposition log (`requestlog.go`, with per-route-shape grouping in `requestgroups.go`), the uncached-traffic SHAPE capture + implementation brief (`shapes.go` + `brief.go`), and the web dashboard (`dashboard.go` + embedded `web/`)
- `internal/api/web/` — Dashboard front-end: `src/*.ts` (the only source) compiled to `assets/*.js` (gitignored build output, embedded; CI builds it)
- `cmd/server/` — Entry point (drains in-flight fetches before closing the DB on shutdown)

## The global-truth model (operator directive, 2026-07-03)

> "just because nobody has fetched something doesn't mean we get to ignore updates from webhooks for it. there's only 1 cache because there's only 1 true state, the appropriate parts of the cache are revealed to users/apps based on their permission model (i.e. were they able to access this resource directly through github -> yes -> ok we can serve the cache for this resource to them)"

Storage and authorization are **separate axes**:

1. **ONE global truth store.** `repos`, `pull_requests`, `pr_labels`, `commit_checks`, `workflow_runs`, `contents_cache`, `git_commits_cache`, `git_commit_miss_cache`, `pulls_list_cache`, `commits_list_cache`, `compare_cache`, `commit_ci_cache`, `workflow_runs_cache`, `pull_files_cache`, `closed_pull_cache`, `pull_diff406_cache`, `branches_list_cache` carry NO actor column — there is one row per fact because there is one true state. Webhooks and every principal's fetches all maintain the same rows. (`install_token_cache` and `repo_installation_cache` stay keyed by the app principal: a minted token IS per-credential, not shared truth.)
2. **Webhooks ALWAYS apply.** The dispatcher never asks "who has this cached?" — a delivery for a repo nobody ever fetched upserts the `repos` row straight from the payload's own `repository` object (`absorbRepoFromPayload`) and applies. There is no `skipped` disposition, no on-demand pull, and no `ActorsForRepo` gate; those were deleted.
3. **Reads reveal by permission** (`internal/api/reveal.go`). Serving a cached resource requires proof the caller could read it from GitHub directly: the repo is **public** in truth (fast path, no GitHub call), the principal holds a live **access grant**, or a live **probe** (`GET /repos/{owner}/{repo}` with the caller's own token) answers 2xx. Grants are earned only from GitHub's own answers — an org list-sync **replace-syncs** the principal's grants to exactly the repos GitHub returned them (`source=list_sync`), and a successful probe records one (`source=probe`); TTL ~24h (`ghdata.GrantTTL`). Authoritative denials (404, non-rate-limit 403) are cached in `deny_cache` for ~5m (`ghdata.DenyTTL`) and replayed without touching GitHub; transient failures (5xx, 429, rate-limited 403, network) are NEVER cached and fail only that one request. Unknown visibility (`repos.visibility` = `''`) is treated as private — fail closed.

## Key Constraints

- **No migrations** — bump `SchemaVersion` in `internal/database/db.go` to nuke+recreate
- **sqlc codegen** — run `sqlc generate` after modifying `schema.sql` or `queries/*.sql`
- **Freshness/data separation** — `internal/freshness/` must never import GitHub-specific packages
- **Lazy fetches are detached, backoff-gated, and drained** — `freshness.Manager.doFetch` runs the fetch and its metadata writes on a `context.WithoutCancel`-derived context bounded only by `fetchSafetyTimeout` (5m): a client aborting its request cannot kill the shared multi-page org-repos fetch mid-flight or prevent the result from being stored, and a short caller deadline is deliberately NOT re-applied (the old webhook-deadline re-application killed fetches half-done). Every detached fetch is tracked in an inflight WaitGroup; `Manager.Drain(timeout)` waits for them and `cmd/server` calls it after `ListenAndServe` returns, BEFORE `db.Close()` — so a fetch can never write to a closed DB at shutdown. An error-state row inside its `retry_after` window is NOT re-fetched by lazy callers — `EnsureFreshOutcome` reports the stored error instead, so a failing upstream isn't hammered on every request; deliberate refreshes (periodic triggers) bypass the backoff. When `/graphql` serves the stale cache after a refresh failure it sets `X-GSM-Stale: true` + `X-GSM-Last-Fetched` response headers and WARN-logs with the principal — headers only, the body stays identity-test-identical.
- **One global truth, revealed by permission (replaces per-actor isolation)** — the security boundary is the REVEAL LAYER, not
  storage: revealing `owner/repo` to a principal requires the repo to be public, a live grant, or a live probe with THAT
  principal's own token. Fail-closed rules that must not regress: unknown visibility = private; only authoritative denials are
  cached; grants expire; list-sync REPLACE-syncs. docs/reveal-layer.md — principal resolution, the App-identity path, and the
  background App credential.
- **Webhooks always apply (the whole point)** — the dispatcher applies payloads DIRECTLY to global truth, so high-frequency
  events never trigger a re-fetch and a delivery for a repo nobody ever fetched still lands. Invalidation is only a fallback for
  structural events with unparseable payloads. Do NOT regress this into invalidate-and-refetch, and do NOT add a "who has this
  cached?" gate. docs/webhooks/dispatch.md — the per-event matrix and the COALESCE rules that keep a webhook from blanking
  known state.
- **App-identity principal (opt-in, for trusted first-party app callers)** — a *request*-time caller may send a **GitHub App JWT** in the `X-Mirror-Identity` header. `requireAuth` verifies it via `ghclient.VerifyAppIdentity` (`GET /app` — GitHub only 200s if the RS256 signature checks out against the app's public key, so it's unforgeable; cached per-JWT) and resolves that caller to the principal `app:<id>`, skipping the per-user/fingerprint resolution entirely (installation tokens cannot call `/user`). This exists because such a caller's installation tokens rotate hourly — fingerprint principals would lose their earned grants every hour; the app principal keeps **one stable grant set** across all the app's tokens. The `Authorization` token is still injected into the context for upstream fetches/probes/passthrough, so per-repo authorization against GitHub is unchanged. No identity header → the default per-user/fingerprint resolution above.
- **The cache contract (three tiers)** — every data route is exactly one of: (1) the GraphQL org-repos query, byte-identical and
  identity-test-locked; (2) a cached REST route, whose state is absorbed and whose response is REBUILT with every URL field
  dropped; (3) verbatim passthrough, uncached and debounced. There is no "correctly uncached" verdict — a route that still
  forwards is unfinished work.
  docs/cache/three-tier-contract.md — the three tiers in full, the route families, the no-URL-keys invariant, and passthrough debouncing.
- **Subscriber notifications (`internal/notify`)** — authenticated clients register their own webhook endpoints and the mirror
  POSTs them an HMAC-signed notification after a delivery is applied, so consumers stop racing our ingestion. Config lives in a
  SEPARATE SQLite file the SchemaVersion nuke never touches, and fan-out is reveal-gated fail-closed.
  docs/notifications.md — the six invariants: config DB, gating, drained delivery, retries, secrets at rest, the `/_mirror/*` namespace.
- **Timeline wire format + response compression** — `GET /api/timeline` serves a COLUMNAR binary payload to a caller naming `application/vnd.gsm.timeline.v1` EXACTLY, and readable JSON to everyone else (curl/`*/*`/jq). The JSON is safe only because **the chart REFUSES it**: `fetchTimelineBytes` sends one Accept and THROWS on any other content type — an earlier fallback made a drifted Accept a silent downgrade to ~10x the frames. `TestTimelineClientRefusesJSON` drives the BUILT module to pin the refusal; deleting the JSON instead is a rejected fix (it served operators, and the fallback was the defect). The origin is grey-clouded, so the app gzips its own dashboard payloads (`internal/api/compress.go`) — buffered admin endpoints only, never the data plane (pinned header contract; the NDJSON stream must keep flushing).
  - **The FORMAT lives in js-snippets**, both halves: `ui/timeline-wire.js` (the browser decoder + the one-chunk-per-frame driver, imported at runtime like the component) and `github.com/wow-look-at-my/js-snippets/timelinewire` (the Go `Encode`/`Decode` plus the struct-tag `EncodeRows`/`DecodeRows`/`SchemaOf` and the `Wants` Accept match, a nested module this repo imports). Column names are passed IN as a schema, so the library carries no mirror vocabulary and the wire bytes are unchanged — names were never on the wire. A layout change is a NEW version (new magic, new media type) with its own fixture there, never an edit to the existing one.
  - **What is OURS is only the VOCABULARY**, and it is declared where the fields are: the `wire:"name,kind"` tags on `reqtimeline.Event`. `timelinewire.EncodeRows`/`DecodeRows` map tagged structs both ways and `SchemaOf` derives the schema, so no mapping code, name switch, or hand-written schema lives here — `timelinewire.go` is the media type plus `Wants`. Field order within a kind IS wire order. Plus the domain half in `web/src/timeline.ts` (`intervalsGen`/`eventAt`: what a mirror event MEANS). The names are declared TWICE — the tags and the chart's `SCHEMA` literal — and the library never sees a column name, so a disagreement would surface only in the browser as "trailing bytes" on a payload that encoded perfectly; `TestTimelineSchemaMatchesChart` reads the `.ts` and pins them equal.
  - Depth — the format, the BSON/protobuf/row measurements it was chosen over, the frame-budget findings, and the two stated limits: `docs/timeline-wire-format.md`.

- **Installation tokens at rest (security note)** — the token-mint cache stores each minted installation token in SQLite (`install_token_cache.token`). This is the same trust domain as the traffic itself: the mirror already relays these exact tokens in cleartext on every request it proxies, the DB file sits on the same host with the same access, and every row is bounded by the token's own short (~1h) expiry plus the serve-until cutoff. Rows are pruned on write (expired + LRU) and flushed on installation events. Token values are never logged (the request log records method/path/disposition only) and never appear in error messages; keep it that way when touching `respcache.go`.
- **OAuth relay (github.com login endpoints)** — `POST /login/oauth/access_token` and `POST /login/device/code` (`internal/api/oauth.go`, one shared `relayGitHubLogin` core) relay the two browser-blocked `github.com` login endpoints (NOT `api.github.com`): the OAuth code-for-token exchange and the RFC 8628 device-authorization start, each returned with the mirror's CORS headers so a purely client-side app can complete login (GitHub's login endpoints send no CORS headers). The device flow's polling leg (`grant_type` `urn:ietf:params:oauth:grant-type:device_code`) goes through the access_token route unchanged — the body is opaque bytes to the relay. Both are registered outside `requireAuth` (the body is the credential — an OAuth `client_secret`, or just a public `client_id` for the device flow; no bearer token) and forward only the body + content-negotiation headers to fixed URLs (`githubOAuthTokenURL`/`githubDeviceCodeURL`, vars so tests can point them at a fake). They do NOT copy GitHub's `Access-Control-*` (corsMiddleware is the single CORS authority, so no duplicate ACAO). This is why repo-nightmare's `TOKEN_PROXY` points here instead of a standalone CORS proxy.
- **Admin truth browse, grants view + consistency check/reconcile** — `GET /api/cache/data` dumps global truth rows (or one principal's access grants with `?principal=`); `GET /api/cache/check[?org=]` re-fetches truth from GitHub via the App and diffs it, `?stream=1` for live NDJSON progress, `POST ?apply=true` to reconcile. Read-only GET, open PRs only, 503 with no App. Surfaced as the admin Principals tab's buttons. Full field-by-field comparison rules, the raced-during-check classification, and every apply-mode correction: **docs/dashboard/operator-tooling.md**.
- **Dashboard = separate authz model** — the dashboard (`internal/api/dashboard.go`, served at `/`) authenticates a human via GitHub OAuth and authorizes by **login** (`ADMIN_LOGINS`), deliberately distinct from the data API's bearer-token + reveal model. It reports GLOBAL truth totals plus per-principal reveal standing; admins also get the Webhooks / Requests / Rate limit / Timeline tabs (the Webhooks tab additionally reports **missing App event subscriptions** — `ghdata.RequiredWebhookEvents` absent from the retained delivery log, each with what degrades without it; a missing subscription otherwise fails silently, the affected caches just re-fetching forever), the JSON-only `/api/jobs` and `/api/notifications`, and the **implementation brief** (`/api/brief` + its "Capture implementation brief" button under the uncached-routes table). The request log, rate meter, and timeline ring are IN-MEMORY (live views, not audit logs) and reset on restart. Tabs, payload shapes, the passthrough-reason vocabulary, and the sign-in-failure 400 rule: **docs/dashboard/dashboard.md**.
- **TypeScript front-end** — the dashboard's ONLY source is `internal/api/web/src/*.ts`; `npm run build` (tsc) compiles it to `internal/api/web/assets/*.js`, which is a **gitignored build output that is never committed**, embedded via `//go:embed`. Work only in the `.ts` — the `.js` is disposable, regenerated on demand, never hand-edited and never added to git. The embed names each `.js` file, so a missing one is a Go COMPILE error: `npm run build` must run before any Go build or test (CI's `build` job runs `npm ci && npm run build` ahead of `go-toolchain` for exactly this reason). CI's `web-check` job is the type-check gate (`npm ci` + `npm run build` on the locked toolchain, tsc exits non-zero on any error) and it FAILS if any generated `.js` is tracked (`git ls-files internal/api/web/assets/*.js` must come back empty) — so a second, staleable copy of the front-end can never re-enter the tree. Hand-written `assets/style.css` stays tracked. `assets/demo-data.js` is preview-only (NOT embedded); the CI `preview` job injects it to deploy a backend-free styling preview to buildhost per branch. Each `src/*.ts` emits its own standalone ES module loaded by its own `<script type="module">` tag in `index.html` — `rate-meter.ts` self-registers the `<rate-meter>` web component; `timeline.ts` self-registers `<gsm-timeline>` (types for its buildhost-URL component import live in the interim ambient shim `src/js-snippets-timeline.d.ts` — types only, keep it minimal). Adding an asset file means wiring it in **three** places: the `//go:embed` + hashed-URL machinery in `internal/api/dashboard.go`, the `index.html` script tag, and the `preview` job's copied-assets list in `ci.yml`. The node TEST HARNESS (`internal/api/testdata/browsercheck.ts` — the real-browser end-to-end frame check) is TypeScript too, type-checked against `src/` by `npm run check:harness` (`tsconfig.harness.json`, noEmit — node runs the `.ts` directly, so there is no build step and nothing lands in `assets/`); CI's `web-check` runs it, so a changed export signature fails the build instead of surfacing mid-measurement at runtime. Playwright (browsercheck only) is deliberately NOT a devDependency — `testdata/playwright.d.ts` is a minimal types-only shim so `npm ci` stays light; `npm i -D playwright` to actually run it.
- **Update-check endpoints** (`internal/api/updatechecks.go`) — `GET /.well-known/docker-updater/{health,pre-update}`, status code
  only, registered OUTSIDE `requireAuth`. That placement is load-bearing: an unrouted path here does not 404, it falls through to
  the passthrough proxy, which answers 401 for a tokenless request — and docker-updater reads any non-404 as "implemented", so
  leaving them unregistered reports the container as permanently unhealthy rather than unconfigured. health pings the cache DB
  (`Store.Ping`); pre-update holds while `freshness.Manager.Busy()` reports a detached fetch in flight.
- **Build** — use `go-toolchain` (not `go build`/`go test` directly); run `npm run build` first on a fresh checkout and after editing `web/src/*.ts` (the JS it emits is gitignored, and `//go:embed` needs it on disk)

## Environment Variables

- `GITHUB_APP_ID` (optional) — GitHub App ID. When set with a private key, the service signs in as this app for background work — periodic refreshes and the source-of-truth fetch for the admin consistency check (`/api/cache/check`); it is never used to serve normal data-API requests, which require the caller's own `Authorization` header (401 otherwise). Unset = periodic refreshes disabled and the consistency check reports "unavailable" (503). Webhooks apply to global truth either way.
- `GITHUB_APP_PRIVATE_KEY` / `GITHUB_APP_PRIVATE_KEY_PATH` — the App's PEM private key (PKCS#1 or PKCS#8), inline (optionally `\n`-escaped) or as a file path (path wins). Required when `GITHUB_APP_ID` is set.
- `WEBHOOK_SECRET` — GitHub webhook HMAC secret
- `LISTEN_ADDR` — HTTP listen address (default `:8080`)
- `DB_PATH` — SQLite database file path (default `github-mirror.db`)
- `SUBSCRIPTIONS_DB_PATH` (optional) — the subscriber-notification config DB, a SEPARATE SQLite file the SchemaVersion nuke never touches. Default derives from `DB_PATH`: strip a trailing `.db`, append `-subscriptions.db` (`github-mirror.db` -> `github-mirror-subscriptions.db`).
- `ALLOWED_ORIGINS` (optional) — comma-separated CORS allow-list for browser clients (e.g. the repo-nightmare PR viewer). Defaults to `*` (any origin), which is safe because the cache reveals data per the caller's proven GitHub access, not origin. Preflight `OPTIONS` is answered without auth; see `internal/api/cors.go`. The middleware also sets `Access-Control-Expose-Headers` (the `X-RateLimit-*` budget + `X-GSM-Cache`/`X-GSM-Stale`/`X-GSM-Last-Fetched`) — without it the CORS default hides every one of them from a cross-origin app, and a REBUILT response has no upstream Expose-Headers list to inherit, so browser clients could read none of them on a cache HIT. The proxy still deliberately keeps GitHub's own Expose-Headers on passthroughs; repeated list-valued header fields combine, so a passthrough exposes the UNION (this only ever widens what a browser may read).
- `CACHE_MAX_ROWS` (optional) — per-table row ceiling for the response caches (sets `ghdata.CacheMaxRows` at startup; default `1000000`). One knob for every cache table: all but `git_commits_cache` are TTL-bounded, so the cap is only a runaway safety net for them; `git_commits_cache` (immutable rows, no TTL) is the one table that actually grows to the ceiling. A value that is unparseable or < 1 fails startup.
- `PASSTHROUGH_DEBOUNCE` (optional) — how long an eligible uncacheable (passthrough) READ is held so identical concurrent requests share one upstream call, as a Go duration string (default `5s`). `0` disables coalescing and forwards immediately. Values that are unparseable, negative, or > 30s fail startup — the window adds latency to every uncacheable read, so a fat-fingered `5m` must fail loudly at boot rather than wedge the API. See the tier-3 passthrough-debouncing paragraph.
- `REFRESH_INTERVAL` (optional) — periodic fleet-refresh cadence as a Go duration string (default `6h`). The first cycle always runs immediately at startup regardless of the interval. A value that is unparseable or not positive fails startup.
- `GITHUB_OAUTH_CLIENT_ID` / `GITHUB_OAUTH_CLIENT_SECRET` (optional) — GitHub OAuth App credentials for dashboard login. If unset, the dashboard still renders but sign-in is disabled. Register the OAuth App's callback as `<BASE_URL>/auth/callback`.
- `SESSION_SECRET` (optional) — HMAC key for session cookies. If unset, a random per-process key is used (sessions reset on restart); set it in production.
- `ADMIN_LOGINS` (optional) — comma-separated logins that get the admin dashboard views (all principals, truth browse, consistency check; default `PazerOP`); case-insensitive.
- `BASE_URL` (optional) — public base URL (e.g. `https://github-state-mirror.pazer.io`) used to build the OAuth `redirect_uri`; derived from the request (honoring `X-Forwarded-Proto`) when unset.
